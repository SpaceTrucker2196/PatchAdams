# Patch Adams — factory runbook

## 0. TL;DR

```
git clone git@github.com:SpaceTrucker2196/PatchAdams.git
cd PatchAdams
make test        # swift test --enable-code-coverage — must exit 0
make build       # xcodegen + xcodebuild, warnings are errors
make harness     # parse every fixture patch, apply each to its base
make bases       # regenerate Fixtures/bases from the patches (only after
                 # changing a fixture or SyntheticBase; the tests catch drift)
```

If `make test` is green and `make build` produces no warnings, the
factory is operational.

## Layout

```
Package.swift            engine packages + CLI harness (SwiftPM, no deps)
Sources/PatchModel/      unified-diff parser → Patch/FileChange/Hunk/Line
Sources/BaseLoader/      read-only base: directory, git revision (the only Process use), tar/tgz/zip
Sources/ApplyEngine/     in-memory apply with fuzz → post text, LineMap, ApplyReport
Sources/DiffEngine/      Myers (linear space) + patience line diff, Myers token diff, unified output
Sources/patchadam/       CLI harness: parse, hunks, synth-base, apply, diff
Tests/*Tests/            XCTest per engine; FixtureTests walks Fixtures/patches
Fixtures/patches/        10 invented patches (kettle, lantern, scaffold, rename, mail) — the gate set;
                         tools/fixtures/make_fixtures.py writes them (D10)
Fixtures/bases/          synthetic base per fixture, generated by `make bases` (D4)
Fixtures/archives/       sample.tar / .tar.gz / .zip / -stored.zip for ArchiveBase tests
App/                     SwiftUI shell: SessionController (state + Engines actor), ScrollSync,
                         Views/ (MainView, FileTreeView, ColumnView, CodeTextView + LineGutterView,
                         WelcomeView), DebugHooks (debug-only launch flags, see below)
project.yml              xcodegen spec; PatchAdams.xcodeproj is generated, gitignored
docs/spec.md             the product spec (Oct 14, 2026)
docs/dark-factory.md     pattern + autonomy contract
docs/converge.md         one production order → shipped
wiki/                    knowledge base, published by pages.yml
tools/                   audit-workflows.sh, billing/ledger.py
```

All six packages from docs/spec.md "Packages" have landed:
`AlignmentEngine` with M3, `SessionModel` with M4.
Dependency rules are in `Package.swift`'s header comment and
`AGENTS.md`.

## Toolchain

- macOS 14+ target; built on macOS 27 / Xcode 27 / Swift 6.4 as of
  2026-10-14. Package tools-version 6.0, language mode 6, strict
  concurrency.
- `xcodegen` (Homebrew) for the app project. Engines need only
  `swift`.
- No third-party dependencies. Git access is by shelling out to the
  system `git` (spec, Stack). Adding a dependency is a stops-and-asks.

## CI

- `.github/workflows/test.yml` — on push to `main`: `swift test
  --enable-code-coverage`, then the harness over every fixture.
  Post-hoc judge only; the merge gate is local green pre-push.
- `.github/workflows/pages.yml` — publishes `wiki/` to GitHub Pages.
- `make audit` checks both against the three lab findings
  (SECURITY.md). Run it before adding any workflow.

## Cold-start sanity loop

1. Fresh clone.
2. `make test` → exit 0 (19 tests at scaffold time).
3. `make build` → zero warnings (project.yml treats them as errors).
4. `make harness` → one parse block and one apply report per fixture,
   every file `clean`, exit 0.

## Release: DMG and notarization (D2, M5)

    make dmg                         # ad-hoc signed: builds, mounts, runs locally
    make dmg notarize SIGN='Developer ID Application: river.io llc (U3Z59VXPUB)'

`make release` builds the Release configuration with the hardened
runtime and signs it with `SIGN` (default `-`, ad-hoc); `make dmg`
wraps the app and an Applications link in a compressed DMG at
`.build/PatchAdams-<MARKETING_VERSION>.dmg` (the version comes from
`project.yml`); `make notarize` submits that DMG with the App Store
Connect API key on this box (`NOTARY_KEY_ID`, `NOTARY_ISSUER` in the
Makefile; the `.p8` lives in `~/.appstoreconnect/private_keys/`),
waits, staples, and checks it with `spctl`. Notarization needs a
*Developer ID Application* identity, which only the account holder can
create; `make notarize` refuses an ad-hoc signature up front.

On GitHub, `.github/workflows/dmg.yml` builds the same ad-hoc DMG
when a tag containing "Release" is pushed (`git tag v0.6.0-Release &&
git push origin v0.6.0-Release`) and attaches it to that tag's release;
it can also be run by hand from the Actions tab (artifact only).

## Driving the window from a shell (debug builds)

`App/DebugHooks.swift` reads launch arguments so the factory can check
the viewer gates and take screenshots without a hand on the mouse:

    .build/DerivedData/Build/Products/Debug/PatchAdams.app/Contents/MacOS/PatchAdams \
      --demo --file internal/service/brew_task.go \
      --select A:10-20 --scroll A:150 --stress --shot /tmp/patchadam.png

`--demo` opens kettle-1…18 on a merged synthetic base; `--patches
a,b` opens any patches the same way; `--select` copies the reference
for a display-line range and logs it; `--scroll` scrolls one column and
logs where every column landed; `--stress` times a 10,000-line render;
`--shot` self-renders the window to a PNG (a `screencapture -l` of a
window on a secondary display can be stale — the PNG is the truth).
M3 flags: `--golden B` sets a column golden and logs the re-render
time; `--search "text"` logs hits per file and column with the first
display lines; `--pin` pins the `--select` region; after `--select`
every other column's anchor (status, confidence, lines, nearest hunk)
is logged. M4 flags: `--open <pkg>` opens a `.patchadam` session;
`--blind`; `--finding "A:10-20|title|category|severity[|notflagged]"`
(repeatable); `--rank "A=1,B=2"`; `--rationale`; `--save <pkg>`;
`--export-md <file>`; `--state` logs columns, golden, findings, pins,
ranks and the blind mapping, and whether the blind prompt is up; the
first hook line logs the detected `git`, the code font in force and
the blind-prompt flag. The hooks run in stages (+3 s session
setup, +5 s selection, +8 s persist, +11 s screenshot) because a golden
switch re-lays the text views and would drop a selection made in the
same instant.
Every step logs `hook: …` to stderr.

## Code visualization (cygnus)

This repo is meant to be legible in **cygnus** — our code-viz tool
(`~/projects/cygnus`, macOS). It models the system as a knowledge
graph from repository evidence, renders it as a 2D pattern visualizer
(cycles, coverage, callers, roles), and doubles as this factory's ops
dashboard. Register the repo once, re-index after large changes:

    cd ~/projects/cygnus/CygnusCore
    swift run cygnus register ~/projects/PatchAdam
    swift run cygnus index

Or add it in the app, which also installs/refreshes the factory.

Keeping the picture honest is a repo-side job. Cygnus reads:

- **Source, directly** — Swift under `Sources/`, `Tests/`, `App/`;
  no build required.
- **Factory docs** — `MISSION.md`, `AGENTS.md`/`CLAUDE.md`,
  `FACTORY.md`, `PROGRESS.md`, `ROADMAP.md`, `README.md`, and
  markdown under `docs/` (so `docs/spec.md` reaches the dashboard).
- **`LEDGER.md` / `METRICS.md` / `DECISIONS.md` tables** — parsed
  *positionally* by column order. Keep the shipped headers and column
  order exactly; a renamed or reordered column silently drops rows
  from the dashboard. `LEDGER.md` is machine-owned (read-only in the
  app), `METRICS.md` and `DECISIONS.md` are append-only.
- **`docs/converge.md` steps** — numbered `N. **Title.** detail…`.
  Keep that shape or the loop stops rendering.
- **Commit subjects** — `(closes #N)` / `fixes #N` / `resolves #N`
  links a commit to its production order; `chore(ledger):` and
  metrics commits are recognised and kept out of throughput.
- **Coverage rings** — the oracle runs with `--enable-code-coverage`.
  On Swift 6.4 the llvm-cov export lands at
  `.build/out/Products/Debug/codecov/PatchAdam.json` (older
  toolchains: `.build/<triple>/debug/codecov/*.json`). Cygnus only
  ever reads what a test run produced.
- **CI flow** — no `Fastfile`, so `Makefile` targets (`test`,
  `build`, `harness`, `audit`) and the two workflows are the diagram.
  Name targets for what they do.
- **GitHub Pages** — the `wiki/` site shows as a live preview.
